# Superpowers 技能自动调用规则

## 强制规则

1. **在做出任何回复或行动之前，必须先扫描所有可用技能**，判断是否有任何技能适用于当前任务。

2. **1% 规则**：如果你认为某个技能有哪怕 1% 的可能性适用于你正在做的事情，你就必须调用该技能。如果某个技能适用于你的任务，你没有选择，必须使用它。这不是可协商的，这不是可选的。

3. **技能优先级**：
   - 过程技能优先（brainstorming、debugging）—— 这些决定如何处理任务
   - 实现技能其次 —— 这些指导执行
   - "打造 X" → 先 brainstorming，再实现技能
   - "修复这个 bug" → 先 debugging，再领域特定技能

## 禁止的合理化念头（红旗）

如果出现以下任何念头，立即停止，必须先检查技能：

| 念头 | 现实 |
|------|------|
| "这只是一个简单的问题" | 问题就是任务，检查技能 |
| "我需要先了解更多上下文" | 技能检查在澄清问题之前 |
| "让我先探索代码库" | 技能告诉你如何探索，先检查 |
| "我不需要正式技能" | 如果技能存在，就使用它 |
| "我记得这个技能" | 技能会演化，读取当前版本 |
| "这个技能小题大做了" | 简单事情会变复杂，使用它 |
| "我先把这件事做了" | 在做任何事情之前先检查 |
| "这不算任务" | 行动 = 任务，检查技能 |
| "我知道那是什么意思" | 知道概念 ≠ 使用技能，调用它 |

## 指令优先级

1. 用户的显式指令 — 最高优先级
2. Superpowers 技能 — 在冲突时覆盖默认系统行为
3. 默认系统提示 — 最低优先级

## 当前已安装的技能

| 技能 | 触发条件 |
|------|----------|
| brainstorming | 任何创造性工作（功能/组件/行为修改）之前 |
| systematic-debugging | 遇到 bug、测试失败、异常行为时 |
| test-driven-development | 实现功能或 bug 修复之前 |
| writing-plans | 有多步骤任务的规范/需求时 |
| executing-plans | 有书面实现计划要执行时 |
| subagent-driven-development | 执行具有独立任务的实现计划时 |
| dispatching-parallel-agents | 面对 2+ 个独立无依赖任务时 |
| verification-before-completion | 声称工作完成/修复/通过之前 |
| using-git-worktrees | 需要工作隔离时 |
| finishing-a-development-branch | 实现完成、测试通过后 |
| requesting-code-review | 完成任务或合并前 |
| receiving-code-review | 收到代码审查反馈时 |
| writing-skills | 创建/编辑技能时 |
